what it is

LinkLocal is a peer-to-peer messenger that runs over your local WiFi. no internet, no problem — every node keeps a local ledger, and the moment any device on the mesh comes back online, the queued history is pushed to a federated Matrix room.

think IRC, but the rooms are local, the keys are local, and the whole thing is end-to-end encrypted.

project status

NOT WORKING the Matrix bridge is not active. there is code for it (bridge/matrix_sync.py) but it is not loaded by the entry point and has not been tested end-to-end against a real homeserver. do not configure MATRIX_* env vars and expect messages to leave your machine yet.

in plain terms: local chat between laptops on the same WiFi works. pushing that history to Matrix when the internet comes back does not. it is the next big thing to wire up.

the matrix bridge is not working yet. the rest of the project is.

what works today

  • local P2P chat over WiFi via mDNS auto-discovery
  • end-to-end encrypted messages (PyNaCl, sign-then-encrypt)
  • multi-room (public + password-protected)
  • terminal UI with rooms, peers, and live chat
  • offline-first: messages typed without internet are saved locally and shown in your history immediately
  • one-liner install + locallink launcher

what is stubbed or unfinished

  • Matrix bridge (code exists, not wired in, untested)
  • no message redelivery to peers that came back online (local peer re-join does not replay missed history)
  • no per-room topic / member list / role UI in the TUI
  • no file or image transfer
  • no web UI (TUI only)

known sharp edges

  • mDNS does not work on networks with AP isolation enabled (cafes, some corporate WiFi)
  • only one process per port — two locallink instances on the same machine need different LOCALLINK_PORT
  • peer identity is per-folder; moving locallink.db to a new machine is a new identity
  • the bridge may be deleted on package install if its folder is not listed in pyproject.toml (already wired in, just noting)

install

standalone executable (zero dependencies)

download the pre-built LocalLink.exe from the latest GitHub release and double-click to launch. no python, no pip, no setup — just download and run.

to build the exe yourself from source:

pip install -r requirements.txt pip install pyinstaller python build.py # executable lands at dist/LocalLink.exe

pip (python required)

one command, three platforms. if you have python 3.10+ and pip, you're done.

pip install git+https://github.com/m7md2323/LinkLocal.git
linux · macOS · windows — same command everywhere

then run:

locallink

if "locallink" is not recognized

the command is installed but your shell can't find it. two quick fixes:

windows (PowerShell): pip install --user (the default when system python isn't writeable) drops scripts in %APPDATA%\Python\Python3XX\Scripts\ which isn't on $PATH. either add it permanently, or just use python -m locallink instead:

# one-time fix for this terminal: $env:PATH = "$env:APPDATA\Python\Python313\Scripts;$env:PATH" # permanent fix (current user): [Environment]::SetEnvironmentVariable('Path', "$env:APPDATA\Python\Python313\Scripts;$([Environment]::GetEnvironmentVariable('Path','User'))", 'User') # or skip the PATH problem entirely: python -m locallink

linux/macOS: pip installs to ~/.local/bin/. add it to PATH:

export PATH="$HOME/.local/bin:$PATH" # add to ~/.bashrc or ~/.zshrc to persist locallink

if you don't have pip

it comes with python. on most linux distros: sudo apt install python3-pip (debian/ubuntu) or sudo dnf install python3-pip (fedora). on macOS: brew install python or download from python.org (tick "Add to PATH"). on Windows: download from python.org and tick "Add Python to PATH" in the installer.

for contributors

git clone https://github.com/m7md2323/LinkLocal.git cd LinkLocal python3 -m venv venv && source venv/bin/activate # or: python -m venv venv (Windows) pip install -r requirements.txt python run.py

if you need locallink on your PATH without activating a venv, these do the same thing as pip but create a dedicated venv in your home dir:

quick start

  1. install (above)
  2. run locallink
  3. type into the bottom bar. default room is ready.
  4. other laptops on the same WiFi auto-appear in the peer list.
  5. Ctrl+N new room, /j <room_id> join remote, /leave exit one.

offline? everything you type is saved to your local sqlite ledger immediately. when you (or any peer) reconnects, the bridge flushes the queue to Matrix.

architecture

four layers. each one is a single python file you can read in 5 minutes.

[01] mesh

mDNS discovery + Flask HTTP listener. peers auto-find each other on the LAN. every inbound message is verified and decrypted before it lands in storage.

[02] storage

SQLite + Peewee. four tables: peers, rooms, memberships, messages. one boolean per message: is_synced. that's the whole offline-first contract.

[03] security

PyNaCl. each device has one signing key (Ed25519) and one box key (X25519). private keys never leave the disk they're generated on.

[04] bridge

background worker. polls the unsynced queue, pushes to a Matrix room via REST. restarts are safe; in-flight events are keyed by the local message id.

[05] ui

Textual TUI. 3-pane: rooms, peers, chat. RichLog for scrolling messages, worker-thread internet probe, keyboard-first everything.

[06] cli

one entry point (run.py). loads .env, bootstraps the self peer, starts everything in the right order, hands the terminal to the TUI.

configuration

copy the example and edit. nothing is required to start.

cp .env.example .env nano .env

common knobs:

  • LOCALLINK_NODE_ID — stable peer identity (otherwise a fresh UUID per launch)
  • LOCALLINK_DISPLAY_NAME — your name in the peer list
  • LOCALLINK_PORT — local HTTP port (default 5000)
  • MATRIX_ACCESS_TOKEN — only needed if you wire up the bridge
